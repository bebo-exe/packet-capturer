📊 Ruleset Experiment Guide

The Ruleset Experiment is an advanced feature for comparing string search algorithms.

What Does It Do?

The system captures network packets and uses one randomly selected packet and uses its payload as a search pattern. It then compares three different algorithms to find how many times this pattern appears in all captured packets.

How It Works:

  1. Setup: Select a network interface and choose how many packets to capture (minimum 1000)
  2. Capture Phase: Captures packets from the selected interface and displays progress
  3. Pattern Selection: Randomly selects one packet as the search pattern
  4. Algorithm Comparison: Searches for the pattern using three different algorithms simultaneously
  5. Results Display: Shows how many matches each algorithm found and how long it took

The Three Algorithms:

1. Quick Search (Built-in)
Uses Python's native string matching ('in' operator). Simple and fast for most cases. O(n*m) worst case complexity.

2. Boyer-Moore
Advanced algorithm that skips characters to reduce comparisons. Excellent for longer patterns. O(n/m) best case, O(n*m) worst case.

3. Aho-Corasick (KMP)
Finite automaton-based matching, guaranteed linear time. Best for large datasets. O(n+m) complexity.

Understanding Results:

  • Matches: Number of times the pattern was found in all packets
  • Time (ms): Milliseconds taken to complete the search
  • Complexity: Theoretical time complexity of the algorithm

Tips for Best Results:

  • Use 1000-3000 packets for balanced results and reasonable time
  • Avoid >10,000 packets on slower systems
  • Run on an active network interface (WiFi/Ethernet) for better traffic
  • Run multiple experiments for consistency
  • You can stop the experiment at any time using the "Stop" button

Stop Button:

The ⏹ Stop Experiment button appears during capture and allows you to halt the experiment before reaching the target packet count. If you stop before capturing 1000 packets, you'll be warned but can continue anyway.

Sequential Execution:

Each algorithm is run one after the other, showing the results for each in turn.

Parallel Execution:

All algorithms run simultaneously, allowing you to compare their performance in real-time.
